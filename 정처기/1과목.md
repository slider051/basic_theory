## 소프트웨어 설계

클래스 :객체를 만들기 위한 설계도(템플릿)이자, 객체의 속성과 동작을 정의하고 이를 바탕으로 객체를 생성하기 위한 틀이다.

GoF(Gang of Four) 디자인 패턴 : "객체지향 프로그램에서 자주 발생하는 설계 문제를 해결하기 위한 검증된 설계 방법(재사용 가능한 설계 템플릿) 23가지."

생성, 구조, 행위  (구분 기준) -> 객체를 어떻게 만들까? 어떻게 연결할까? 객체들이 어떻게 소통할까? 

- 어댑터(디자인패턴) :  호환되지 않는 인터페이스를 가진 두 객체가 함께 일할 수 없게 만드는 문제를 해결하기 위해 사용
>> 실제 자바에서는 어떻게 쓰이는가?
"""자바에서 List와 Array 간의 변환을 어댑터 패턴의 예시로 들 수 있다. 예를 들어, 배열 형태로 구현된 정렬 알고리즘을 List 객체에 적용하고 싶을 때, 어댑터를 사용하여 List를 Array로 변환하고 정렬 후 다시 Array를 List로 변환하는 방식으로 활용할 수 있다. 복잡한 알고리즘의 경우, 기존 구현을 재사용하는 것이 효율적일 수 있다"""

- 옵저버(행위패턴) : 한 객체의 상태가 바뀌면 여러 객체에게 자동으로 알려준다. (유튜브 구독 - 알림)

소프트웨어 공학의 기본 원칙 : 1) 품질 높은 소프트웨어 상품 개발 , 2) 지속적인 검증 시행, 3) 결과에 대한 명확한 기록 유지

미들웨어 : RPC → 원격 함수 호출 , MOM → 메시지 큐(비동기형) , ORB → 객체 통신, TP-Monitor → 트랜잭션 처리, WAS → 웹 애플리케이션 실행
비동기적 전달 : 보내는 쪽과 받는 쪽이 동시에 기다리지 않고, 각자 자기 일을 하다가 나중에 처리하는 방식

Agile 프로세스 모델: 계획보다는 변화에 반응 

XP의 5가지 가치 : 용기, 피드백, 의사소통, 단순성, 존중

오버라이딩 = 부모 메서드를 자식 클래스가 같은 이름으로 재정의
-> 같은 매소드 호출이 객체에 따라 다르게 동작하므로 '다형성'이다.

추상화 : 공통적인 특징을 뽑아 설계하는 것

MVC 모델에서 모델은 데이터와 비즈니스 로직을 담당한다.
=> 하나의 모델을 여러개의 View 가 공유할 수 있다.

예시) 동일 사용자 정보 (model) -> 웹화면, 모바일, 관리자화면 등등

사용자가 기입(입력)에서 오류가 나오는 경우
- 생략 오류, Transcription(한자리를 잘못 입력) Transposition(순서 바뀜), 이중 오류, 추가 오류(addition Error)

객체 지향 설계 원칙 : 개방-폐쇄, 의존-역전, 인터페이스 분리, 단일 책임 원칙

휴리스틱 알고리즘 : 정확한 최적해 대신, 경험적 방법으로 빠르게 좋은 해를 찾는 알고리즘
예시) 모든 경우 탐색하기 어려울때 사용 (힐 클라이밍, A* 알고리즘, 그리디 탐색)

소프트웨어 버전 관리 도구 : GIT, 빗키퍼, CVS, SVN (Marven은 빌드 자동화 도구이다.)
파일의 변경 이력을 저장하고, 이전 상태로 되돌리거나 변경 내용을 추적하는 것
